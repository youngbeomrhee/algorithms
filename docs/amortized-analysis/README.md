# 분할상환분석 (Amortized Analysis)

## 개념 설명

**분할상환분석(Amortized Analysis)**은 일련의 연산들에 대한 평균 비용을 계산하는 알고리즘 분석 기법입니다. 가끔 발생하는 비싼 연산의 비용을 여러 저렴한 연산들에 분산시켜, 전체적인 평균 성능을 계산합니다.

### 핵심 아이디어

- **최악의 경우(Worst Case)**: 단일 연산의 최대 비용
- **분할상환 비용(Amortized Cost)**: 연속된 n개 연산의 평균 비용
- 가끔 발생하는 O(n) 연산이 있더라도, 전체적으로는 O(1) 평균을 유지할 수 있음

### 왜 중요한가?

실제 상황에서는 최악의 경우가 드물게 발생하고, 대부분의 연산이 빠르게 수행됩니다. 분할상환분석은 이러한 실제 성능을 더 정확하게 반영합니다.

## 비유로 이해하기

**커피 구독 서비스**를 생각해보세요:

- 매달 30,000원을 지불 (일정한 비용)
- 한 달에 커피를 10잔 마심
- 분할상환 비용: 커피 한 잔당 3,000원

실제로는:
- 어떤 날은 커피를 2잔 마심 (6,000원 가치)
- 어떤 날은 커피를 0잔 마심 (0원)
- 하지만 평균적으로는 한 잔당 3,000원

**동적배열도 마찬가지입니다:**
- 대부분의 삽입: O(1) - 그냥 추가
- 가끔 발생하는 삽입: O(n) - 배열 확장 시 복사
- 분할상환 비용: O(1) - 평균적으로는 상수 시간

## 동적배열 분할상환분석: 완전 가이드

### 동작 방식

1. 초기 용량으로 배열 생성 (예: 1)
2. 요소를 추가하다가 배열이 가득 차면:
   - 현재 크기의 **2배 용량**으로 새 배열 생성
   - 모든 요소를 새 배열로 복사
   - 새 요소 추가

### 간단한 예시 (n=32)

| 연산# | 추가비용 | 복사비용 | 총비용 | 누적비용 | 분할상환비용 | 용량 |
|-------|----------|----------|--------|----------|--------------|------|
| 1 | 1 | 0 | 1 | 1 | 1.00 | 1 |
| 2 | 1 | 1 | 2 | 3 | 1.50 | 2 |
| 3 | 1 | 2 | 3 | 6 | 2.00 | 4 |
| 5 | 1 | 4 | 5 | 12 | 2.40 | 8 |
| 9 | 1 | 8 | 9 | 24 | 2.67 | 16 |
| 17 | 1 | 16 | 17 | 48 | 2.82 | 32 |
| 32 | 1 | 0 | 1 | 63 | 1.97 | 32 |

**관찰**:
- 복사는 2, 3, 5, 9, 17번째에 발생 (2의 거듭제곱 + 1)
- 복사 직후: 분할상환 비용 급증 (최대 2.82)
- 2의 거듭제곱 위치(2, 4, 8, 16, 32): 분할상환 비용 최저

## 수학적 증명 (CLRS 표준)

### 문제의 핵심: 왜 실제 값이 공식과 다른가?

처음 분석 시 혼란스러운 점:
- **공식**: 분할상환 비용 = 2 - 1/n
- **실제 데이터**: n=17일 때 2.82, n=5일 때 2.40

**이유**: 공식은 **두 가지 경우**를 구분해야 합니다!

### 경우 1: n = 2^k (2의 거듭제곱)

n = 2^k개를 **이미 삽입 완료**한 상태:

**복사 발생 이력:**
```
2번째 삽입: 1개 복사 (용량 1→2)
3번째 삽입: 2개 복사 (용량 2→4)
5번째 삽입: 4개 복사 (용량 4→8)
...
2^(k-1)+1번째: n/2개 복사 (용량 n/2→n)

마지막 복사는 용량 n/2 → n 확장 시
```

**총 비용:**
```
삽입 비용 = n
복사 비용 = 1 + 2 + 4 + ... + n/2
         = 2^0 + 2^1 + ... + 2^(k-1)
         = 2^k - 1
         = n - 1

총 비용 = n + (n - 1) = 2n - 1
```

**분할상환 비용:**
```
(2n - 1) / n = 2 - 1/n

예시:
n=2:  3/2 = 1.50
n=4:  7/4 = 1.75
n=8:  15/8 = 1.875
n=16: 31/16 = 1.9375
n=32: 63/32 = 1.9688 ✓
```

### 경우 2: 복사 직후 (n = 2^k + 1)

n = 2^k + 1번째를 **방금 삽입**한 상태:

**이 순간의 특징:**
```
방금 2^k개를 복사함 (매우 비싼 연산!)
복사 비용 = 1 + 2 + 4 + ... + 2^(k-1) + 2^k
         = 2^(k+1) - 1

총 비용 = n + (2^(k+1) - 1)

분할상환 비용 ≈ 2.8~2.9
```

**실제 데이터:**
- n=3: 6/3 = 2.00 (방금 2개 복사)
- n=5: 12/5 = 2.40 (방금 4개 복사)
- n=9: 24/9 = 2.67 (방금 8개 복사)
- n=17: 48/17 = 2.82 (방금 16개 복사) ✓

### 경우 3: 일반적인 n (상한 증명)

2^k < n < 2^(k+1)인 임의의 n:

```
복사 비용 ≤ 1 + 2 + 4 + ... + 2^k < 2n
총 비용 < 3n
분할상환 비용 < 3
```

**결론**: 모든 n에 대해 **상한은 3**입니다 (CLRS 증명).

## 핵심 통찰: 복사 비용 표기의 정확한 의미

### 질문 1: `1 + 2 + 4 + ... + n/2`가 맞나?

✅ **맞습니다!** n개 삽입 완료 시의 복사 비용입니다.

**이유:**
- n개 삽입 시 용량은 ≥ n
- 마지막 복사는 용량 n/2 → n 확장 시 발생
- 이때 n/2개를 복사
- 용량 n → 2n 확장은 아직 발생 안 함 (n+1번째부터)

### 질문 2: 왜 실제 분할상환 비용이 2를 초과하나?

**답변**: 복사가 **방금 발생한 순간**을 측정했기 때문입니다.

```
시간 흐름:
───────────────────────────────────────>

n=16 완료: 1.9375 (최저점, 2 - 1/16)
    ↓
n=17 삽입: 16개 복사 발생! (큰 비용)
    ↓
n=17 완료: 2.82 (급증!)
    ↓
n=18~32: 비용 1인 연산들 (점진적 하락)
    ↓
n=32 완료: 1.97 (다시 최저점, 2 - 1/32)
```

**패턴:**
- 복사 직후: 급증 (2 초과)
- 2의 거듭제곱: 최저 (2 - 1/n)
- 점근적: 2로 수렴

## 세 가지 분석 방법 (CLRS Chapter 17)

### 1. 집계 방법 (Aggregate Method)

n개 연산의 총 비용을 직접 계산:
```
총 비용 < 3n
분할상환 비용 = 총 비용 / n < 3
```

### 2. 회계 방법 (Accounting Method)

각 삽입에 **3 크레딧** 부과:
- 1 크레딧: 즉시 삽입에 사용
- 2 크레딧: 미래의 복사를 위해 저축

**불변식**: 배열의 후반부 n/2개 요소가 각각 2 크레딧 보유

복사 발생 시:
- n개를 복사해야 함
- 후반부 n/2개가 각각 2 크레딧 = 총 n 크레딧
- 정확히 n개 복사 비용 지불 ✓

### 3. 퍼텐셜 방법 (Potential Method)

퍼텐셜 함수: `Φ(T) = 2 × size - capacity`

**복사 없는 삽입:**
- 실제 비용: 1
- ΔΦ = 2
- 분할상환 = 1 + 2 = 3

**복사 있는 삽입:**
- 실제 비용: n + 1
- ΔΦ = 2 - n
- 분할상환 = (n + 1) + (2 - n) = 3

**모든 경우 분할상환 = 3**

## 다른 분할상환분석 예제

### 1. Stack의 MultiPop

```python
def multi_pop(stack, k):
    for _ in range(min(k, len(stack))):
        stack.pop()
```

- 단일 MultiPop: O(k)
- n개 push + 임의의 pop/multipop: O(n) 총 비용
- 분할상환: O(1)

**이유**: 각 요소는 최대 1번만 pop 가능

### 2. Queue (Two Stacks)

```python
class Queue:
    def __init__(self):
        self.input_stack = []
        self.output_stack = []

    def enqueue(self, x):
        self.input_stack.append(x)  # O(1)

    def dequeue(self):
        if not self.output_stack:
            # 모든 요소를 이동 (비싼 연산!)
            while self.input_stack:
                self.output_stack.append(self.input_stack.pop())
        return self.output_stack.pop()
```

- 대부분: O(1)
- 가끔: O(n) (stack 이동)
- 분할상환: O(1)

**이유**: 각 요소는 최대 2번만 이동 (input→output, output→삭제)

### 3. Binary Counter

```python
def increment(counter):
    i = 0
    while i < len(counter) and counter[i] == 1:
        counter[i] = 0  # carry
        i += 1
    if i < len(counter):
        counter[i] = 1
```

- n번 증가 시 비트 변경 총 횟수: O(n)
- 분할상환: O(1)

**이유**:
- 최하위 비트: n번 변경
- 두 번째 비트: n/2번 변경
- 세 번째 비트: n/4번 변경
- 총: n + n/2 + n/4 + ... < 2n

## 추론 및 보정 과정 요약

### 1단계: 초기 분석
- 복사 비용 = 1 + 2 + 4 + ... + n/2 = n - 1
- 분할상환 비용 = 2 - 1/n ≈ 2

### 2단계: 실제 데이터와 불일치 발견
- 실제: n=17일 때 2.82, n=5일 때 2.40
- 공식: 2 - 1/17 = 1.94, 2 - 1/5 = 1.8
- **왜 2를 초과하는가?**

### 3단계: 표기법 검증
- `1 + 2 + 4 + ... + n/2` 표기가 맞는가?
- ✅ 맞다! n개 삽입 완료 시의 복사 비용
- n/2는 마지막 복사 시 복사하는 개수

### 4단계: 학계 표준 조사
- CLRS, Cornell CS3110, Interview Cake 참고
- **발견**: 두 가지 경우를 구분해야 함
  1. n = 2^k (완료): 2 - 1/n
  2. 복사 직후: 일시적으로 상승
  3. 일반적인 n: 상한 3

### 5단계: 정확한 이해
- 복사 직후 = 방금 큰 비용 발생 → 평균 상승
- 이후 저렴한 연산들이 평균을 낮춤
- 2의 거듭제곱 위치에서 최저점 도달
- **모든 경우 상한은 3 (CLRS 증명)**

## 요약

### 핵심 공식

**n = 2^k (2의 거듭제곱):**
```
복사 비용 = 1 + 2 + 4 + ... + n/2 = n - 1
총 비용 = 2n - 1
분할상환 = 2 - 1/n ≈ 2
```

**일반적인 n:**
```
복사 비용 < 2n
총 비용 < 3n
분할상환 < 3
```

### 실제 동작

- **최저점**: 2의 거듭제곱 위치 (2, 4, 8, 16, 32, ...)
- **최고점**: 복사 직후 (3, 5, 9, 17, ...)
- **평균**: 점근적으로 2에 수렴
- **상한**: 3 (보장)

### 최종 결론

> 동적배열의 삽입 연산은 **O(1) 분할상환 시간**을 가지며,
> 실제 비용은 **평균 약 2, 최대 3**입니다.
>
> 이것이 바로 **분할상환분석의 힘**: 가끔 발생하는 O(n) 연산을
> 여러 O(1) 연산들로 상쇄하여 전체 평균을 O(1)로 유지합니다.
